Navbar Cart Icons

Puts a Shopping Cart icon and a Checkout icon beside the hamburger button of a ZCA Bootstrap navbar, on phones and tablets, whenever the cart has something in it. No template file is changed.

What it does

On a phone or tablet, where ZCA Bootstrap collapses its navigation into a hamburger, it puts two icons right beside that hamburger as soon as the cart has something in it:

  Phone, something in the cart:

  Hare Do            [cart] [card] [☰]

  Phone, empty cart:

  Hare Do                          [☰]

  Desktop: nothing changes. The navbar is expanded and its own
  Shopping Cart and Checkout links are in view.

The cart icon opens the shopping cart page and the card icon goes straight into checkout — the same two pages ZCA Bootstrap's own Shopping Cart and Checkout menu entries lead to, built with the same calls and carrying the same labels. A customer no longer has to open the menu to get to either.

Each icon is a 44px touch target with finger room between them and before the hamburger. Install it and they're there. Nothing to configure unless you want to.

Why it exists

ZCA Bootstrap collapses the whole navigation into the hamburger on a phone, including the Shopping Cart and Checkout links it adds once something is in the cart. So the two things a buying customer most wants are two taps away and out of sight. A client asked for the cart and checkout icons to sit next to the hamburger instead, where every other shopping app puts them.

The first version was a hand edit of the template's tpl_header.php. It worked, and it would have been lost the next time the template was updated. So it became this plugin: the same icons, injected into the rendered page with no template file touched, on any ZCA Bootstrap store, on Zen Cart v1.5.8 through v3.0.0.

Installing

  1. Upload the zc_plugins/NavbarCartIcons/ directory from this package so it lands at <your store>/zc_plugins/NavbarCartIcons/v1.0.0/. Nothing goes anywhere else.
  2. In your admin, go to Modules → Plugin Manager, select Navbar Cart Icons, and click Install.
  3. Open your storefront on a phone (or narrow the browser window) and add something to the cart. The icons are beside the hamburger.

The installer creates a Navbar Cart Icons group under Configuration. If the menu entry doesn't show straight away, log out of the admin and back in; Zen Cart caches the menu per session.

Your store needs to be running ZCA Bootstrap (3.3.0 or later) or a clone of it. On responsive_classic or any other template the plugin installs fine and does nothing at all: there's no hamburger of that kind to sit beside.

Settings

Configuration → Navbar Cart Icons. Thirteen settings; the defaults are right for most stores.

The switch

SettingDefaultWhat it does
Enable Navbar Cart Icons?trueMaster switch. false hides the icons everywhere without uninstalling; Plugin Manager then lists the plugin as Navbar Cart Icons - Mod Not Turned On.

What is shown

SettingDefaultWhat it does
Show The Shopping Cart Icon?trueThe first icon, linking to the shopping cart page.
Show The Checkout Icon?trueThe second icon, linking straight into checkout. Only ever shown while the cart has something in it.
Show The Cart Icon When The Cart Is Empty?falsefalse matches ZCA Bootstrap's own menu, which lists Shopping Cart and Checkout only once there's something in the cart. true shows the cart icon on every page regardless; the checkout icon still waits for an item.
Show The Item Count On The Cart Icon?falsetrue adds a small badge with the number of items in the cart, and adds the count to the icon's accessible name.
Shopping Cart Icon Class:fas fa-shopping-cartThe Font Awesome classes for the cart icon. Any icon your template's Font Awesome includes: fas fa-shopping-basket, fas fa-shopping-bag. Letters, digits, spaces and hyphens only.
Checkout Icon Class:fas fa-credit-cardThe Font Awesome classes for the checkout icon: fas fa-cash-register, fas fa-money-check.

How it looks

SettingDefaultWhat it does
Keep Everything On One Line?trueLets a store name, logo or trademark ahead of the icons shrink and clip with an ellipsis rather than push the icons and the hamburger onto a second line. See below.
Load The Plugin Stylesheet?trueLinks the plugin's small stylesheet and applies the four settings below. false if you'd rather style #navbarCartIcons from your own template CSS.
Icon Color:emptyAny CSS color. Empty means the navbar's own link color. A value that doesn't look like a color is ignored.
Icon Hover Color:emptyThe color under a pointer or keyboard focus. Empty means the navbar's own hover color.
Icon Size:1.5remAny CSS size. The touch target stays at least 44px square whatever the size.
Space Between The Icons:10pxThe gap between the two icons, and between the last icon and the hamburger.

If you set an icon color, check its contrast against your navbar; an icon nobody can see isn't much of a shortcut.

Keeping everything on one line

The navbar is a wrapping flex container. Whatever your template puts ahead of the icons — a brand, a logo, the Trademark plugin's mark — has a fixed width, and on a 320px phone, or with a large-text setting, brand + icons + hamburger can exceed the bar. Bootstrap then wraps the hamburger onto a second line, which looks broken.

With Keep Everything On One Line? on, the plugin gives the navbar's first item a zero flex basis and lets it clip: it takes whatever room is left and shows an ellipsis when that isn't enough, and the icons and the hamburger never move. This applies only while the navbar is collapsed, so the desktop layout is untouched.

If your brand is an image that mustn't be clipped, switch the setting off and size the image yourself, or hide just its text on tiny screens from your template CSS. A store whose logo already carries the name can use:

@media (max-width: 359.98px) {
  #navMain nav.navbar:has(#navbarCartIcons) .tradeMark { font-size: 0; }
}

Styling

Spacing, size and colors come from the settings and are written into the page as one inline rule just before </head>. Everything else is in the stylesheet:

zc_plugins/NavbarCartIcons/v1.0.0/catalog/includes/templates/template_default/css/navbar_cart_icons.css

Three ways to change it, in increasing order of commitment:

  1. Use the settings. Color, hover color, size and spacing cover most needs.
  2. Add rules to your template's own CSS. The plugin's link and inline rule go into <head> after your template's stylesheets, so a plain #navbarCartIcons .nav-link rule of yours loses on order. Raise the specificity and yours wins: #navMain #navbarCartIcons .nav-link { color: #9a044f; }
  3. Take over the stylesheet. Copy navbar_cart_icons.css into includes/templates/YOUR_TEMPLATE/css/. The plugin checks there first and links that copy instead of its own. Then, if you'd rather set colors and spacing in CSS too, switch Load The Plugin Stylesheet? off.

What the plugin inserts is one Bootstrap nav list, <ul id="navbarCartIcons" class="navbar-nav flex-row ml-auto d-lg-none">, holding one nav-item per icon, each a nav-link with the icon inside it and the label as its title and aria-label. The d-lg-none comes from the navbar's own navbar-expand-lg class, so a template that expands at a different size gets a matching d-md-none or d-xl-none.

How it works

No Zen Cart notifier fires inside the header template, and a plugin can't override a template file. So the plugin opens an output buffer at NOTIFY_HTML_HEAD_END (just before </head>), closes it at NOTIFY_FOOTER_END (just before </body>), and on the way out finds the navbar's toggler button and inserts the icons immediately ahead of it. Both notifiers exist on every Zen Cart release from v1.5.8 and in ZCA Bootstrap's own templates. On a request with nothing to show — an empty cart, with the empty-cart icon off — no buffer is opened at all.

Nothing is added to a page that already carries an element with id="navbarCartIcons", which is what lets a template with a hand edit of the same thing coexist with the plugin.

Coming from a hand edit

If you added the icons to your template by hand before this plugin existed:

  1. Install the plugin first. It sees the hand edit's #navbarCartIcons and adds nothing, so nothing changes on the storefront yet.
  2. Remove the hand edit from your cloned template's tpl_header.php, and any #navbarCartIcons rules from its CSS — or keep the CSS if you prefer it to the settings, with its specificity raised.
  3. Reload. The plugin's icons are now the ones you see, in the same spot.

There's never a moment with no icons showing.

Upgrading the plugin

  1. Upload the new version directory alongside the old one, so zc_plugins/NavbarCartIcons/ holds both. Don't delete the old one yet; Plugin Manager needs both to offer the upgrade.
  2. Modules → Plugin Manager → Upgrade.
  3. Once it reports success, the old version directory can be deleted.

Your settings survive an upgrade. Labels and help text are refreshed to the current version; values you've changed are never touched.

Uninstalling

Modules → Plugin Manager → Navbar Cart Icons → Uninstall. This removes the configuration group, all of its settings, and the admin menu entry. No template file was ever changed, so there's nothing else to undo. To remove the code as well, delete zc_plugins/NavbarCartIcons/ afterwards.

To hide the icons without uninstalling, set Enable Navbar Cart Icons? to false.

Troubleshooting

The icons don't appear

  • Is there something in the cart? With an empty cart nothing shows unless Show The Cart Icon When The Cart Is Empty? is true.
  • Is Enable Navbar Cart Icons? true?
  • Are you looking at a phone-sized window? On a desktop the navbar is expanded and the icons are hidden by design.
  • View the page source and search for navbarCartIcons. If it's there but invisible, set Icon Color: the icons are probably the same color as the bar.
  • If it isn't in the source, the plugin didn't find a ZCA Bootstrap navbar (a <nav> with the navbar class holding a navbar-toggler button). On responsive_classic or any other template the plugin does nothing.

The icons show as empty boxes

The Font Awesome class names you entered don't exist in the Font Awesome version your template loads. The defaults are known to both Font Awesome 5 and 6; check any others on fontawesome.com for your version.

The hamburger dropped onto a second line

Keep Everything On One Line? is false, or your navbar's first item isn't the one taking the room. See Keeping everything on one line.

The stylesheet 404s

Zen Cart's shipped zc_plugins/.htaccess denies everything then explicitly re-allows .css, .js and .html, so on a normal Apache host the stylesheet (and this Read Me) are served from the plugin directory. If your server ignores .htaccess — nginx, LiteSpeed without compatibility mode, Apache with AllowOverride None — you may need a rule permitting those types under zc_plugins/.

After upgrading, the old styling is still showing

Browsers cache the stylesheet for up to an hour. A hard reload (Ctrl+F5) clears it. Each plugin version lives in its own directory, so a new version is always a new URL.

The admin menu entry is missing after installing

Log out and back in. If it's still missing, uninstall and re-install; that rewrites the admin_pages record.
